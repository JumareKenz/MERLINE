01 Executive Summary

The product in this repository is called Merline, not Merlin. It is an AI-branded MERL platform — Monitoring, Evaluation, Research and Learning — aimed at NGOs, governments and research institutions. It is built around quantitative survey work: projects, studies, logframes, indicators, questionnaires, enumerator assignments, and form submissions.

Against the proposed qualitative interview product, the honest summary is that the surrounding scaffolding exists and the interview pipeline does not. There is a competent web dashboard, a multi-module REST API, and a 40-model Postgres schema. There is no interview entity, no interview guide, no transcript, no finding or quotation, no consent record, no audio capture, no transcription, no PWA, and no offline storage on the client.

Three findings that change the picture

1. The backend API cannot currently authenticate anyone. Tokens are signed without issuer/audience claims but verified with them, so every authenticated request fails. I reproduced the failure directly. Confirmed

2. The AI layer fabricates answers when it cannot reach a provider. AiGatewayService falls back to a hand-written "simulated response" that is returned through the same success path as a real model answer. Separately, all nine "specialist agents" are hard-coded template strings that never call a model at all. Confirmed

3. The polished dashboard is largely running on mock data. The frontend ships an 800-line in-process mock adapter (lib/api-mock.ts) that serves demo projects, studies, submissions and AI sessions when NEXT_PUBLIC_USE_MOCK=true. Screenshots of a working product do not imply a working backend path. Confirmed

Maturity

This is an early prototype with production-shaped packaging. The repository contains extensive planning documentation asserting far more completeness than the code supports — PROGRESS.md claims 1,230 backend tests, 600 frontend tests, and a designed 62-table schema; the repository contains two test files, one of which fails to run, and 40 models. README.md states the backend is Laravel/PHP and the mobile app is Flutter; the backend is NestJS/TypeScript and no mobile application source exists. Treat the docs as aspiration, not as a description of the system.

What genuinely works, assuming the auth defect is fixed: CRUD across organizations, users, roles, projects, studies, logframes, indicators, questionnaires (with sections, questions, options, skip logic, validations, translations), assignments, submissions, media upload to local disk, a delta sync API, dashboards, notifications, audit log storage, and an AI chat endpoint that can reach OpenAI.

04 Existing User Roles and Permissions

The database models a complete RBAC system: Role, Permission, RoleUser, PermissionRole, all scoped by organizationId. Roles are per-organization with a slug unique within the org and an isSystem flag. Confirmed

The seed creates three roles — Administrator, Viewer, Enumerator — and one demo admin user with a hard-coded weak password. Registration creates a new organization and a role for the registering user in a transaction. Confirmed

The frontend declares a permission matrix of 12 modules × 7 actions (view, create, edit, delete, approve, export, invite) in lib/permissions.ts, with wildcard support (module.*), and uses it to hide UI. Confirmed

Permissions are not enforced anywhere on the server

PermissionGuard and TenantGuard are both implemented and neither is ever applied. A repository-wide search for @UseGuards(PermissionGuard), TenantGuard, or the @Permissions() decorator returns only the definition files themselves. Every controller uses @UseGuards(JwtAuthGuard) and nothing more. The effective authorization model is "any authenticated user can do anything". Confirmed

ThrottlerModule.forRoot is registered but no APP_GUARD binds ThrottlerGuard, so rate limiting is also inert. Confirmed

For the interview product, the roles named in the brief — administrator, researcher, manager, field interviewer, reviewer/approver — do not exist as seeded roles, and no permission slugs cover interviews, transcripts, findings, or consent. Not found

No encryption at rest, no signed URLs, no lifecycle/retention rules.

Cross-cutting: the sync push defect

SyncService.push creates a SyncBatch whose primary key is a generated UUID, while the local batchId variable is stored in the separate batchId column. At the end it calls prisma.syncBatch.update({ where: { id: batchId } }) — looking up the column value as a primary key. That record does not exist, so Prisma raises P2025 and the request fails with a 500 after all changes have already been written and logged. The client sees a failed sync for work that actually landed, and will likely retry it. Confirmed by code reading

08 AI and Transcription Capabilities

Transcription

None exists. There is no speech-to-text code, dependency, configuration key, queue, or model in the repository. This is the largest single build item for the proposed product. Confirmed

What the AI layer actually does

There is exactly one path that reaches a real language model: POST /api/v1/ai/chat → AiService.chat() → AiGatewayService.sendMessage(). It builds an OpenAI-style /chat/completions request and posts it with a Authorization: Bearer header.

ProviderConfigured endpointWill it work?
OpenAI…/v1/chat/completions, BearerYes — correct shape
Anthropic…/v1/chat/completions, Bearer + anthropic-versionNo — the API is /v1/messages with an x-api-key header and a different body/response shape. Model ids are also undated aliases.
Google…/v1/chat/completions, BearerNo — Gemini uses :generateContent with a different auth and payload
OpenRouter…/api/v1/chat/completions, BearerYes — OpenAI-compatible

The fabricated-response fallback

sendMessage loops over every provider that has a key. If all of them throw — or if no key is configured at all — it does not raise. It returns generateSimulatedResponse(): a hand-written block of MERL-flavoured filler ("Based on the available information and best practices in MERL… 1. I have analyzed the key aspects of your request…"), tagged model: 'simulated', provider: 'fallback', cost: 0.

That object flows through the normal success path into AiMessage and back to the user interface. Whether a given answer came from a model or from a string literal is recorded only in a metadata field that no inspected UI component surfaces. For a product whose output will inform programme decisions about real beneficiaries, this is the highest-severity design flaw in the codebase. Confirmed

The nine "specialist agents"

research-design, survey-design, indicator, data-quality, reporting, knowledge, qualitative, executive, translation — all exposed at POST /ai/agents/{type} and routed by AgentOrchestratorService.

None of them calls a model. Each process() returns a template literal of generic advice, optionally interpolating the user's message and a count or two from the database. The abstract base class SpecialistAgent declares no gateway dependency and the orchestrator injects none, so this is structural rather than incidental. The QualitativeAgent — the one closest to this product — returns a fixed bulleted list recommending informed consent and thematic analysis. Confirmed

RAG and citations

DocumentChunk carries an Unsupported("vector(1536)") embedding column. RagService.ingestDocument splits text into 2,000-character chunks with 200-character overlap and inserts them — without ever computing an embedding. RagService.search does a Prisma contains (case-insensitive substring) and then sorts by a local word-overlap score. There is no vector search, no pgvector index, and no reranking. A UI component ai-citation-card.tsx exists and renders a quote plus a source string, but nothing in the backend produces the citation data it would display. Confirmed

Guardrails and cost tracking

GuardrailService applies a small regex blocklist — <script>, DROP TABLE, DELETE FROM, SQL comment markers — and length caps of 100k input / 500k output characters. This defends against nothing relevant: it does not address prompt injection, and /DELETE\s+FROM/i or /--\s+.*$/m will false-positive on ordinary interview transcript text. AiInference rows do capture model, provider, token counts, computed cost and latency, which is a genuinely useful foundation for cost control. Confirmed

Evidence linkage — the core product requirement

Nothing in the system links an AI output to a source. There is no span model, no offset or timecode anchor, no quotation entity, and no schema path from a generated sentence back to the audio or transcript it came from. "Evidence-linked findings and quotations" is a from-scratch build. Not found

Conflict handlingPartialServer-side last-write-wins: on UPDATE, the client's updatedAt is compared to the server's and the write is silently dropped if older. No merge, no user-facing conflict resolution, no vector clocks. The SyncLog.conflict column is only populated with an exception message.
Binary syncMissingmedia is in the sync entity map, but the push protocol carries a JSON payload — audio bytes cannot travel this path. There is no story for syncing a queued recording.

The mobile/ directory contains nine detailed design documents describing a Flutter app with Drift/SQLite, delta sync, SQLCipher and remote wipe. None of it is implemented — there is no Dart code in the repository. For the proposed PWA, these documents are useful requirements input and nothing more.

Confirmed defects

CriticalJWT issuer/audience mismatch breaks all authentication

AuthModule signs with { secret, signOptions: { expiresIn } } — no issuer, no audience. JwtStrategy verifies with issuer: 'merline' and audience: 'merline-api'. I reproduced this with the installed jsonwebtoken: JsonWebTokenError: jwt audience invalid. expected: merline-api. Every authenticated request against the real backend returns 401. Confirmed by execution

CriticalAccess tokens expire after 7 seconds

parseInt(configService.get('jwt.expiresIn', '604800'), 10) is applied to a configuration default of the string '7d'. parseInt('7d', 10) evaluates to 7, which jsonwebtoken interprets as seconds. Verified: a token signed this way has exp - iat = 7. The same expression appears in both auth.module.ts and auth.service.ts. Confirmed by execution

CriticalCross-tenant data exposure on list and detail endpoints

StudiesService.findAll and SubmissionsService.findAll build their where clause from query parameters only — there is no organizationId filter, and the controllers do not inject one from the token. ReportsService.findAll is the same. ProjectsController.findAll takes organizationId from the query string, so it is caller-controlled.

Detail endpoints are equally open: findById for studies, projects, submissions and media looks up by primary key with no tenant check, and GET /media/:id/download streams any file to any authenticated user who knows its UUID. With PermissionGuard and TenantGuard unused, nothing compensates. Confirmed

HighPassword-reset and verification tokens stored in plaintext

resetPasswordToken and emailVerificationToken are plain String? columns. Anyone with read access to the users table can take over any account. These should be stored hashed. Confirmed

HighRate limiting configured but not enforced

ThrottlerModule.forRoot([{ ttl: 60000, limit: 60 }]) is imported, but no APP_GUARD provider binds ThrottlerGuard. Login and the AI endpoints — the two places that most need it, for credential stuffing and for token spend — are unthrottled. Confirmed

HighSeeded demo administrator with a weak hard-coded password

prisma/seed.ts creates admin@merline.org with a short hard-coded password, marks the email verified, and prints the credentials to stdout. If the seed is ever run against a shared or production database this is an immediate full-tenant compromise. Confirmed

12 Technical Risks and Gaps

Critical

CriticalAuthentication is non-functional

JWT claim mismatch plus a 7-second expiry. Nothing can be validated end-to-end against the real API until this is fixed, which also means none of the "working" features have ever been exercised through the live stack.

CriticalUnsupported AI conclusions — fabricated fallback

The gateway silently substitutes invented text for a model response on any provider failure, and all nine specialist agents are static templates. Applied to interview analysis, the system can present fabricated "findings" about vulnerable people as AI output, with no visible marker. Compounded by the absence of any evidence-linking mechanism.

CriticalSensitive personal data with no protective controls

Interview audio and transcripts are special-category data. Today there is no consent record, no retention limit, no PII handling, no encryption at rest, no access check on media download, and no redaction before content is sent to third-party model providers.

CriticalCross-tenant data exposure

List and detail endpoints do not scope by the caller's organization, and both authorization guards are unused. One customer's interviews would be reachable by another's users.

CriticalAudio storage is ephemeral and single-node

Files are written to local disk — /tmp/uploads under Vercel. Recordings that field teams may have travelled hours to collect can be irrecoverably lost. Irreplaceable data with no durability guarantee is the worst possible combination.

CriticalOffline-first is claimed but entirely absent

No service worker, manifest, IndexedDB, outbox, or retry. The stated core use case — recording interviews in low-connectivity field settings — is unbuildable on the current client. Field teams would lose recordings on any network interruption.

High

HighPoor audio quality has no mitigation path

No level metering, no pre-flight microphone check, no noise floor or clipping detection, no minimum-bitrate enforcement, no duration probe, and no quality score. Field recordings on cheap handsets in noisy environments are the norm, and transcription accuracy degrades sharply. The Submission.qualityScore field exists for form data and has no audio analogue.

HighSpeaker attribution has no model and no correction path

No diarization, no Speaker entity, no speaker labels, and no UI to reassign a turn. In a two-or-more-person interview, misattributing a statement to the interviewer rather than the participant invalidates the quotation. Without a correction workflow, errors propagate into findings and reports unchallenged.

HighTranscription and storage costs are unmodelled

AiInference tracks text tokens only. There is no audio-minute accounting, no per-organization quota, no budget cap, and no storage-growth model. A single 90-minute interview is roughly 80–170 MB of uncompressed audio and a meaningful STT spend; a study of 200 interviews is a material and currently invisible cost line. The 50 MB upload cap will also reject many real interviews.

HighSync push fails after writing

The SyncBatch primary-key defect makes every push return 500 having already committed its changes, inviting duplicate retries. Combined with last-write-wins and no idempotency key, offline reconciliation is not trustworthy.

HighNo audit trail in practice

The interceptor almost certainly never fires; where it would, it records no before-values and no checksum. For research ethics and donor assurance, "who listened to, edited, or approved this interview" must be answerable. It currently is not.

HighZero effective test coverage on a deploy pipeline with a manual production gate

Two test files, one unrunnable. The canary deploy machinery is elaborate but rests on no correctness signal, and its Helm charts and health endpoints do not exist.

HighNo database migrations

No prisma/migrations directory, yet deploy runs prisma migrate deploy. The schema has only ever been applied via db push. There is no reproducible schema history and no rollback path — a serious problem before any production data exists, and a blocking one after.

Medium

MediumReport formats are rigid and non-configurable

A fixed three-section template with hard-coded prose, ignoring Report.config and ReportTemplate.config, and no export renderer for any of the three advertised formats. Donor reporting demands per-funder structures; this needs rebuilding as a real template engine rather than extending.

MediumChunked upload is not production-safe

Loses MIME type and media type, never links chunks to media, never verifies checksums, does not await stream flush, has no expiry or orphan cleanup, and writes chunks to the same ephemeral disk.

MediumDocumentation contradicts the code

README.md names Laravel/PHP and Flutter; PROGRESS.md claims completeness that does not exist; .env.example describes a Laravel stack the app never reads. Any engineer onboarding from the docs will build on false assumptions.

MediumClient declares endpoints the server does not implement

/ai/assist/generate-summary, /ai/assist/extract-themes and the other four assist routes, plus /auth/sessions and the /teams/* family, are declared in api-client.ts with no backend counterpart. The mock adapter hides this in demo mode.

MediumTwo divergent deployment targets

EKS/Helm in CI, Vercel artifacts in both apps, and a media service that branches on process.env.VERCEL. Neither path is complete; the storage behaviour differs between them in a data-losing way.

MediumGuardrails will corrupt legitimate interview text

/DELETE\s+FROM/i and /--\s+.*$/m will match ordinary transcript content and reject it as "blocked content", while providing no defence against actual prompt injection from transcript text — which is the real threat in this product.

Low

LowStale model identifiers and pricing table

The gateway hard-codes Claude 3 / GPT-4o / Gemini 1.5 aliases and a per-1k-token price map that will drift from reality and silently mis-report cost.

LowLoose typing at API boundaries

@CurrentUser() user: any and const where: any are pervasive, discarding the type safety the stack otherwise provides.

LowUntracked binaries and OS files in the repo root

Screenshots, desktop.ini, logo/ and idea/ are untracked working-tree clutter; desktop.ini suggests a cloud-synced folder, which can corrupt node_modules and git state.

LowNo monorepo tooling

No root package.json or workspace config; the two apps are installed and versioned independently with no shared types package, so API contracts are duplicated by hand.

13 Recommended Next Steps

Immediate fixes — days, before any new feature work

  1. Repair authentication. Add issuer/audience to signOptions (or remove them from the strategy), and fix the expiry parsing so '7d' is passed through as a duration string rather than parseInted. Add a test that signs and verifies a token. Without this nothing else can be validated.
  2. Close the tenant boundary. Apply TenantGuard globally, derive organizationId from the token rather than the query string, and add an organizationId filter to every findAll and an ownership check to every findById — starting with media download. Then apply PermissionGuard with real @Permissions() decorators, and bind ThrottlerGuard as an APP_GUARD.
  3. Make the AI layer fail loudly. Delete generateSimulatedResponse and propagate provider errors. If a demo mode is needed, gate it behind an explicit flag and label it unmistakably in the UI. Fix or remove the Anthropic and Google provider entries rather than leaving them to fail into the fallback.
  4. Fix the sync push defect (update the batch by its real primary key) and the audit interceptor's route parsing, and hash reset/verification tokens at rest.
  5. Make CI honest. Add the missing test:ci script and vitest config, add or remove the Playwright job, add a /health endpoint, and either commit the Helm charts or cut deploy.yml back to what actually exists. Generate a real initial Prisma migration.

MVP product work — the interview pipeline

  1. Move media to durable object storage. The AWS SDK is already a dependency. Write to S3 (or a compatible service) with server-side encryption, serve via short-lived signed URLs, raise the size cap to something realistic for a 90-minute interview, and accept audio/webm. This is a prerequisite for every subsequent step and the single highest-value change available.
  2. Model the interview domain. Add InterviewGuide (versioned, reusing the questionnaire versioning pattern), Interview, Recording, Transcript, TranscriptSegment (with start/end offsets and a speaker), Speaker, Finding, Quotation (anchored to a segment and time range), and Consent. Design the evidence link as a first-class foreign key from the outset — retrofitting it later is the expensive path.
  3. Introduce a job queue and a transcription service. There is no async infrastructure at all today. Add a queue, then a transcription worker with retry, progress, and a real use of the existing ProcessingStatus enum. Choose a provider on language coverage and diarization quality (§14), and record audio-minute cost per organization alongside the existing token accounting.
  4. Build the PWA recording client. Manifest and icons, a service worker, IndexedDB for queued recordings and guide content, MediaRecorder capture with level metering, and a resumable background-sync outbox that drives the existing chunked upload endpoints once they are fixed. Treat "the recording is safe on the device until the server confirms it" as the central invariant.
  5. Build the review and approval surface. A transcript editor with synchronized playback, segment editing, speaker reassignment, an edit history, and an explicit approval step that freezes a transcript version before findings are drawn from it. Model AI output as a proposal that a human accepts or rejects, and make every proposed finding carry its quotation and timecode. Generalize the three existing approve/reject patterns into one reviewable-entity mechanism.

Later enhancements

  1. Rebuild reporting as a real template engine that reads ReportTemplate.config, composes approved findings with their evidence, and renders genuine PDF/DOCX/CSV output. Add a scheduler to make ReportSchedule functional.
  2. Make RAG real — generate embeddings, add a pgvector index, use the vector(1536) column that already exists, and wire the existing ai-citation-card component to genuine retrieved sources.
  3. Add qualitative analysis depth — a codebook, thematic coding across interviews, saturation tracking, and inter-coder agreement. This is what distinguishes the product from a transcription tool.
  4. Complete the compliance layer — retention schedules with automated purge, consent withdrawal that cascades, DSAR export/erasure, PII redaction before third-party inference, observability, and SSO/MFA.

In plain English

What Merline can do today: it is a web dashboard and API for managing quantitative research projects. You can set up an organization and users, create projects and studies, build detailed survey questionnaires with skip logic and translations, define indicators and logframes, assign fieldwork to enumerators, review and approve submitted form data, view dashboards, and ask an AI chat assistant general questions. Much of what has been demonstrated so far runs on built-in mock data, and the live backend currently cannot log anyone in because of a token configuration mistake.

What it cannot do: anything in the proposed interview product. It cannot record audio, work offline, install as an app on a phone, transcribe speech, identify who said what, link an insight back to the moment in the recording it came from, capture consent, or produce a real report file. Its AI does not analyse your data — eight of the nine "agents" return fixed advice text, and when the AI service cannot reach a provider it invents a plausible-sounding answer rather than reporting an error.

What needs building: first, a short round of repairs — fix login, stop one organization from seeing another's data, and make the AI fail honestly instead of inventing answers. Then the interview pipeline itself, which is largely new construction: durable cloud storage for audio, a database design for guides, interviews, transcripts, quotations and consent, a background job system with a transcription service, an offline-capable recording app, and a review screen where a person listens, corrects and approves before any finding reaches a report. The existing platform is a reasonable foundation to attach that to — but it is a foundation, not a head start on the interview work itself.
